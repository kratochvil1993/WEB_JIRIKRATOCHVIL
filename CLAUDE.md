# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Static one-page site for Jiří Kratochvíl — web/e-shop developer and portrait photographer. Content is in Czech (`lang="cs"`). Pure HTML/CSS/JS, no framework, no build tools, no package manager.

## Git workflow

Commit and push are two separate approvals — never assume one implies the other. Commit directly to `main` (no feature branches) when asked to commit, but do **not** run `git push` unless explicitly told to push (e.g. "pushni") — a push to `origin/main` triggers an immediate Netlify deploy, so it needs its own go-ahead even right after a commit was requested.

## Commands

There is no build, lint, or test tooling in this repo. To preview locally, serve the root over HTTP (opening `index.html` via `file://` breaks relative fetches/CORS for some assets):

```bash
python3 -m http.server 8000
# then open http://localhost:8000/index.html
```

All pages load the minified `*.min.css`/`*.min.js`, not the sources — `style.min.css` everywhere, `script.min.js` on `index.html`, `page.min.js` on the subpages (`web.html`, …). After **any** edit to `script.js`, `page.js` or `style.css`, regenerate the matching minified file (requires Node, via `npx`, no local install needed):

```bash
npx terser@5 script.js --compress --mangle --comments false -o script.min.js
npx terser@5 page.js --compress --mangle --comments false -o page.min.js
npx clean-css-cli@5 -o style.min.css style.css
```

Commit the regenerated `script.min.js`/`page.min.js`/`style.min.css` along with the source change — there is no Netlify build step (see Deployment below), so the minified files are what actually ship. Forgetting this means the site keeps serving stale CSS/JS.

Photos in `assets/images/` are committed as-is (no build-time image pipeline). If a new/replacement photo comes in oversized for how it's actually displayed (check the CSS — cards here render at well under half the viewport), downscale and recompress it before committing, e.g.:

```bash
dwebp photo.webp -o photo.png
sips -Z 1200 photo.png            # resize longest side to 1200px, keep aspect ratio
cwebp -q 82 photo.png -o photo.webp
```

Pick the resize width from where the image actually renders (2x its CSS display width covers retina); 1200px has been the right ballpark for the `.photo-card` portraits. Update the `<img>`'s `width`/`height` attributes to match the new pixel dimensions.

## Deployment

Netlify, auto-deploy from the `main` branch on GitHub. `netlify.toml` sets `publish = "."` — **the entire repo root is what gets published**, so only files meant to be public should live there (this is why `_design/` is git-ignored rather than just left in place). Security headers (`X-Frame-Options`, `X-Content-Type-Options`, `Referrer-Policy`) are applied to all paths via `netlify.toml`. `assets/vendor/*` additionally gets a one-year immutable `Cache-Control` there — those files never change in place, so treat a library version bump as replacing the files wholesale, not patching them.

All internal references (`style.min.css`, `script.min.js`, `gdpr.html`) use relative paths — keep it that way for anything new so Netlify serves it correctly regardless of path depth.

## Structure

- `index.html` — the whole one-page site: fixed navbar, `#hero` (with a decorative `.scroll-cue`), `#section-web` (web/e-shop pitch), `#section-marketing` (Google Ads / online marketing pitch), `#section-portrait` (photography pitch), `#section-values` ("Proč se mnou" cards), `#contact` (Netlify Forms contact form), footer. The four `.pin-section`s each start with an `aria-hidden` `.section-ghost` div (giant outlined background title that `script.js` slides horizontally while pinned) — decorative, safe to omit from a new section, but keep it `aria-hidden`.
- `web.html` — subpage "jak pracuji" for web/e-shop (hero, proč to dělám, postup v krocích, technologie, zásady, FAQ, CTA). Calm reading layout, **no pinning**: content fades in on scroll via `.reveal` (`page.js`). It is the **template for the other subpages** (the other subpages): copy it, swap the copy/meta/JSON-LD, keep the sections' CSS classes (`.sub-hero`, `.sub-section`, `.steps`, `.sub-grid`, `.principles` (numbered `.principle-card`s — gradient-filled 01–04 (not outlined: `-webkit-text-stroke` draws a stray inner line on the "4" in variable Inter), deliberately unlike the icon cards of "Technologie"), `.faq`, `.sub-cta`, all at the end of `style.css`). Each subpage inlines its own SVG icon sprite (only the `<symbol>`s it uses, copied from `index.html`), carries its own JSON-LD `@graph` (`WebPage` with `mainEntity` → the `#service-*` node on index, `BreadcrumbList`, `FAQPage`) and its own `<script>document.documentElement.classList.add("js")</script>` in `<head>` (hides `.reveal` only when JS runs). The matching `Service` node on `index.html` points its `url` at the subpage, and the pitch section on the homepage has a "Jak pracuji" pill button to it (placed in the **right column under the graphic** — in the text column it made the pinned panel taller than a 720px-high viewport and pushed the h2 under the navbar). Copy style: first person, short declarative sentences, vykání, no prices, no clients/references.
- `marketing.html` — subpage "jak pracuji" for Google Ads / online marketing (same template as `web.html`; "Technologie" = Google Ads, měření konverzí, produktový feed, přehledy). Honest-promises tone: no guarantees of sales/rankings, no prices. The homepage marketing section has a "Jak pracuji" pill under the SERP/dashboard graphic (right column).
- `kontakt.html` — copy of the homepage contact section (cards with copy buttons, Netlify form, success panel) for the subpages; every subpage's "Napsat mi" button, navbar "Kontakt" and footer "Kontakt" link here, while the homepage keeps its own `#contact` and still points to it. The form is a second `<form name="contact" data-netlify="true">` with **exactly the same fields** as the one in `index.html` (Netlify merges same-named forms, so submissions land in one inbox) — if you add/rename a field in one, change it in both. Its submit/copy logic lives in `page.js` (a port of the block at the end of `script.js`).
- `faq.html` — all FAQs in one place, linked **only from the footer menus** (last item of the footer "Menu" list on every page, incl. the homepage; not in the navbar): a general group plus a verbatim copy of the FAQ of `web.html`, `marketing.html` and `fotografie.html`. It is a copy, so when you change an answer on a subpage, change it here too (the `FAQPage` JSON-LD on both pages must match the visible text). General answers about data/cookies restate `gdpr.html` — keep them consistent with it.
- `fotografie.html` — subpage "jak focení probíhá", same template/classes as `web.html` plus a portrait gallery (`.photo-gallery`, CSS `column-count` masonry for mixed portrait/landscape photos — list the `<figure>`s so that each column ends up about equally tall) and a link to the full portfolio at `https://www.jkratochvil.com/` (+ its Město/Příroda/Glamour categories). Gallery photos live in `assets/images/` under their original filenames; they were taken as-is from the photo site's 1100×733 / 600×900 thumbnails (35–115 kB, no re-encode needed). The homepage portrait section has a "Jak focení probíhá" pill under the photo cards (right column — same reason as for the web button). `alt` texts describe the photo and never name the person; **look at each image before writing its alt** (an earlier pass mixed up two photos by reading them in the wrong order).
- `page.js` / `page.min.js` — lightweight script for subpages only (navbar blur, mobile menu, to-top ring, cursor, blob float, contact copy buttons + Netlify form submit, and the motion layer below). Deliberately **not** `script.js`: that one is hard-wired to index.html's sections (pins, hero scene, particle canvas) and would throw on a subpage. Needs the three vendored GSAP files before it; if GSAP is missing it removes the `js` class so nothing stays hidden. **Subpage motion** (all `transform`/`opacity`/`clip-path`, nothing scroll-scrubbed except the ghost drift; the whole layer is skipped under `prefers-reduced-motion`, where CSS shows everything immediately): hero `h1` is split into letters (`splitChars`, a port of the one in `script.js` + a guard that skips pairs that wrapped onto two lines, e.g. after the hyphen in "e-shopy") which fly together from random positions; the other hero bits (`.hero-in`) fade up after it; `.sub-ghost` (giant outlined word behind the hero, `style="--n:<letters>"` sizes it to the viewport) fades in and drifts with scroll; the hero graphic (`.sub-hero-graphic[data-graphic="code|serp|cards"]`, markup copied from the homepage pinned sections) flies in, tilts with the mouse on desktop, and loops on its own — code⇄wireframe, SERP⇄dashboard (bars + counters), photo-card deck — paused by a ScrollTrigger when the hero is off-screen; `h2.reveal-wipe` wipes in from the left (clip-path is cleared after, and `.is-wiped` keeps it `none` — don't rely on `clearProps` alone, the CSS start state would come back); `.step` numbers pop and their connector draws via the CSS vars `--pop`/`--line`; `.feature-card`s get cursor glow (`--mx/--my`) and a light tilt. The wide AI card in `web.html` ("Technologie") is split in two (`.card-split`): text left, an `.ai-flow` diagram right (four steps, "Já" vs "Agenti" pills; agent steps dashed/outlined) that draws its connector and slides the steps in once via the `--flow` var; `.card-wide` cards get the glow but no tilt (it looks wrong on a card that wide). **Subtle "disintegration/pulse" layer** (tune the `amp` object at the top of the hero block of `page.js`, not the structure; `amp.dist` = px of scroll until the scatter is complete, eased `power2.out` so most of it happens in the first ~100 px): on desktop the h1 letters drift apart/blur/fade as the hero scrolls out (scrubbed, fully reversible — created in the intro tween's `onComplete`, so it never fights the entrance) and the graphic shrinks to 80 %, lifts 60 px and fades to 35 % over the same `amp.dist` and curve (visibly, on purpose — a 96 % shrink went unnoticed; change `scale` in `enableTilt()` to tone it down); two soft rings pulse behind the graphic **once**, when it lands after page load (`.sub-pulse`, inside a `.sub-hero-gfxwrap` that `page.js` creates because `.pin-graphic` has `overflow:hidden`) — deliberately not on every loop flip, that was tried and felt noisy; entering a section briefly "breathes" the background blobs (`scale` only — the blob float uses x/y, so they don't collide); and on desktop with a mouse the ghost word is lit up around the cursor by a masked `::after` copy (`--gx/--gy` are written on the ghost only, never on `:root`). Mobile gets the rings and the blob breathing but not the scatter or the cursor light. Two gotchas: `fromTo` tweens inside a looping timeline need `immediateRender: false` or they hide their target at creation; and the `.reveal` batch uses `overwrite: "auto"` — `true` kills other tweens (steps, cards) on the same element.
- Subpage hero markup (`web.html`, `marketing.html`, `fotografie.html`): `.sub-hero` > `.sub-ghost` + container > row: `col-lg-7` (eyebrow/h1/lead/links with `.hero-in`, h1 without `.reveal`) + `col-lg-5` (graphic). `kontakt.html`/`faq.html` have the ghost and text but no graphic. The one-off generator that produced `kontakt.html`/`faq.html`/JSON-LD lived outside the repo and is **not** re-runnable on the current files (its footer/hero are stale) — edit the HTML directly.
- `gdpr.html` — standalone privacy-policy page, linked from the footer and from the contact form's consent checkbox.
- `sitemap.html` — standalone human-readable sitemap page, linked from the footer. Not to be confused with `sitemap.xml` (the machine-readable one referenced from `robots.txt`) — keep both in sync when a page is added or removed.
- `cookie-consent.js` — Consent Mode v2 banner + GTM loader. GTM is deliberately **deferred** (first pointer/key/scroll/touch event, or ~3.5 s after `load`) so ~300 kB of Google JS stays off the critical path; the consent default in each page's `<head>` and any consent updates just queue in `dataLayer` until then.
- `robots.txt` / `sitemap.xml` — at the repo root (published as-is, no templating). `sitemap.xml` needs a `lastmod` bump on a URL when that page's content meaningfully changes.
- `style.css` — single stylesheet. Defines CSS custom properties (`--purple`, `--magenta`, `--accent2`, `--accent-ice`, `--grad-a`, `--grad-b`, `--grad-angle`, etc.) that `script.js` mutates at runtime to drive the scroll-linked background gradient. This is the file to edit. Palette note: the site is deliberately monochrome azure — `--accent2` (button/icon/bar gradient end) equals the old `--magenta`. `--accent-ice` (a lighter tint) used to end the heading gradients but is **unused now**: the highlighted words in headings (`.gradient-text`, name kept for the ~30 HTML uses) are solid `var(--purple)` — **no gradient-to-light anywhere on the site, on purpose**; don't reintroduce it. A cyan→blue second hue was tried and rejected (clashes with the teal background); add depth with lightness, not a new hue.

- `script.min.js` — generated from `script.js` via the `npx terser` command above (see Commands). This is what `index.html` actually `<script src>`s; it's committed to git since there's no Netlify build step. Never hand-edit it.

## Structured data (SEO)

`index.html` carries the canonical JSON-LD `@graph` (in `<head>`): `Person` (`#person`), `WebSite` (`#website`), `WebPage` (`#webpage`), and one `Service` node per pitch section (`#service-web`, `#service-portrait`, `#service-marketing`). `gdpr.html` and `sitemap.html` each have their own minimal JSON-LD block, but it must reference the shared entities by `@id` (e.g. `"isPartOf": { "@id": "https://jirikratochvil.eu/#website" }`) rather than re-declaring `WebSite`/`Person` inline — inline duplicates create disconnected entities in Google's graph instead of reinforcing the same ones. Each secondary page's JSON-LD is itself an `@graph` of its own `WebPage` node (with its own `@id`) plus a `BreadcrumbList`. **Subpages (`web.html`, `marketing.html`, `fotografie.html`, `kontakt.html`, `faq.html`)** carry a much richer graph, all in their own page's `@graph`: `WebPage` (`datePublished`/`dateModified`, `primaryImageOfPage`, `significantLink`, `mainEntity` → the `#service-*` node), `BreadcrumbList`, the **complete** `Service` node re-declared with the same `@id` as on index (Google reads each URL standalone, so a bare `@id` ref would carry no information; same `@id` means consumers merge it into one entity) plus `url` → the subpage and an `OfferCatalog`, `HowTo` (steps ↔ `#postup-N` ids on the `<li class="step">`), `ItemList` of technologies, `FAQPage` (must equal the visible `<details>` text), and the external portfolio `WebSite` on `fotografie.html`; **every subpage has exactly one `ImageObject`** (its `primaryImageOfPage`; on `fotografie.html` it is the first gallery photo, with `creator`/`creditText`/`copyrightNotice`) — don't add an `ImageObject` per gallery photo or an `ImageGallery` node, that was tried and removed on purpose; `kontakt.html` is a `ContactPage` with a `ContactPoint` (+ a property-only `Person` stub with the same `@id`: `contactPoint`, IČO `identifier`); `faq.html` is a `FAQPage` itself. `Person` and `WebSite` are still only referenced by `@id`. After editing any JSON-LD or FAQ, re-validate: parse every block with `json.loads`, check every `{"@id": …}` reference resolves to a node in some page's graph, `WebPage.url` equals the canonical, schema FAQ equals visible FAQ. No prices/`Offer.price` anywhere (deliberate). If a new top-level page is added, give it the same treatment: page-specific `meta description`/`canonical`/`og:*`/`twitter:*` tags (index.html's are the template) and a JSON-LD `@graph` that links into `#person`/`#website` by `@id` instead of duplicating them.

## External dependencies

Vendored locally in `assets/vendor/` (no `node_modules`, no package manager — files are committed as-downloaded and never hand-edited):

- GSAP 3.12.5 + ScrollTrigger + ScrollToPlugin — `assets/vendor/gsap/`

**No Bootstrap, no icon font.** Bootstrap and Bootstrap Icons were removed (~430 kB raw): the top of `style.css` holds a hand-trimmed layer with only what the pages use (reboot, `.container`/`.row`/`.col-*` grid, navbar, `.form-*`, a few `d-*`/`flex`/margin utilities) — if a template needs a new Bootstrap-style utility class, add it there. Icons are an inline SVG sprite (`<symbol id="bi-…">`, right after `<body>` in `index.html`) used as `<svg class="bi"><use href="#bi-name"/></svg>`; to add an icon, copy its `<path>` from the `bootstrap-icons` npm package (`icons/<name>.svg`) into a new `<symbol viewBox="0 0 16 16">`. The mobile menu's collapse is custom (`setNav()` in `script.js`, height animated with gsap), not Bootstrap's.

**Fonts:** Inter is self-hosted in `assets/fonts/` (variable `wght` 400–800, two woff2 files: `inter-latin` + a Czech-only `inter-latin-ext` subset limited to U+0100–017F, made with `fonttools` `varLib.instancer` + `pyftsubset`). `@font-face` lives at the top of `style.css`, and each page `<link rel="preload">`s both files. No Google Fonts request anywhere (also a GDPR plus). If the font is ever replaced, rename the files too — `/assets/fonts/*` is served `immutable` for a year (see `netlify.toml`).

To upgrade a vendored library, re-download the matching version's files from jsDelivr/cdnjs into the same `assets/vendor/*` paths and commit them — don't switch back to a `<script src="https://…">`/`<link href="https://…">` CDN reference for GSAP.

## Animation architecture (script.js)

Everything is driven by GSAP + ScrollTrigger plus one custom `<canvas>` particle system. Key pieces, in the order they appear:

- **Navbar**: `.scrolled` class toggled past 40px scroll (blur/background transition, CSS-driven).
- **Custom cursor** (`#cursor`): follows the pointer via `gsap.to`; disabled entirely on touch/coarse-pointer devices.
- **Hero typewriter**: cycles through a `roles` array into `#roleText`.
- **Scroll-linked gradient**: a `ScrollTrigger` on `document.body` lerps between color `stops` (one per section) and writes the result into the `--grad-a`/`--grad-b`/`--grad-angle` CSS vars consumed by `style.css`.
- **Hero scroll scene** (`buildHeroScroll()` + `heroPin`): on desktop the hero is pinned for its own height with `pinSpacing: false` (adds no extra scroll — `#section-web` arrives exactly where the pin ends). The h1 and the "Kontaktujte mě" contact title are split into `.split-word`/`.split-char` spans by `splitChars()` (the element gets an `aria-label` with the original text); a scrubbed timeline scatters the letters, drifts/blurs the other hero elements, flies the code graphic across the screen and fires the particle burst. Two non-obvious constraints: (1) the `heroPin` ScrollTrigger is created **synchronously** at script start — creating it after the intro made the hero stay offset by 900px when the page reloaded already scrolled; (2) the timeline itself is built only in `heroTl`'s `onComplete`, because the intro `.from()` tweens animate the same `y`/`opacity` and would clash. The timeline's smoothing is a manual `gsap.to(tl, { progress })` in `onUpdate`, not a `scrub` option.
- **Pinned "scrollytelling" sections** (`buildPinned()`): `#section-web`, `#section-marketing` and `#section-portrait` get pinned via `ScrollTrigger` with `pin: true`; `#section-values` is pinned separately (its pin scrubs which card is "active"). Desktop reveals go through the `epic*` helpers (`epicFrom`/`epicTo`/`epicIn`/`epicOut`), which pick a different entrance per element type (h2 clip-path wipe, eyebrow letter-spacing, blur-in paragraphs, 3D card pop, button pop); `.pin-graphic` is excluded from them and flies in on its own from the side it sits on. This is the most complex/fragile part of the file — changes to section markup must keep the `.fade-el` and `.pin-graphic` selectors intact or the reveal breaks silently. Note `.pin-graphic` itself also carries `.fade-el`, which is why `epicEls` filters it out. `epicIn`/`epicOut` use `overwrite: true`, which is only safe because they target DOM elements — never use `overwrite: true` on shared proxy objects like `heroFx` (it also kills tweens nested in the paused hero timeline).
- **Particle canvas** (`#particle-canvas`): custom rAF loop, not GSAP. `sectionConfigs` defines per-section density/speed/hue/size (and whether particles draw connecting lines); the active config swaps based on which section is vertically centered in the viewport (`updateSectionByScroll`, which reads a matching `sections` id array — keep both arrays in the same order when adding/removing sections). Each particle moves by a constant-speed **drift** (direction `a` slowly rotating) plus a damped **kick** velocity (`vx`/`vy`, ×0.985 per frame) fed by the mouse; size/hue/drift speed ease toward the new section's config via `retarget()`. `heroFx.burst` (hero scroll scene, scrubbed there and back) must **not** feed the kick velocity — it only expands the *drawn* position away from the screen centre (`burstView`, smoothed), leaving `p.x`/`p.y` untouched, so the particles are back in place when you scroll up. `pulseFx` (`pulse()`, fired on entering each section) does kick the particles for real, but each in its own **random direction** (`p.pa`, re-rolled per pulse). A radial outward push (the old behaviour) has nothing pulling the particles back: with the wrap-around band at the canvas edge they all piled up there after a few scrolls and the background went nearly empty (zeroing the velocity on wrap did not help). Before the drift was added the 0.985 damping made particles freeze after ~3s — don't remove the drift without replacing it.
- **`lowPower` flag** (`prefers-reduced-motion` or viewport ≤ 991px): disables/simplifies pinning (including the hero pin and the desktop letter-splitting scroll scene), the `epic*` reveals, `.section-ghost` titles (hidden in CSS), the `.scroll-cue`, the custom cursor, particle link-lines, and card tilt. Particles still render, but the drift is off under `prefers-reduced-motion` (they stand still) and capped at 35 on mobile. **Any animation change needs to be mirrored in both the normal and `lowPower` code paths** — mobile and reduced-motion users get a deliberately simpler experience, not just a slower one.
- **Mobile effects (`mobileFx` = `isMobile && !reduceMotion`)**: phones/tablets without reduced-motion get lightweight, **pin-free** effects, all `transform`/`opacity`/`clip-path`/`filter` on a few elements only — hero h1 letters scatter in on load (`splitChars` + `heroTl`), section `h2`s wipe in via a `clip-path` played as a **timed** tween on entry (`mobileWipe()`, instead of the one-shot fade-up, so `mobH2`/`valuesH2` are excluded from `plainEls`/`valuesPlain`) — it was scrub-linked at first and looked jerky on phones because mobile browsers report scroll position coarsely and late; the same goes for hiding: `leaveEl` may only reset an element silently once it's fully off-screen (`end: "bottom top"`); an instant reset while it's still visible (the old `bottom 12%`) showed up as elements popping out under the navbar, and scrolling back up uses a short fade (`leaveEl(el, true)`); keep anything that's a visible "reveal" time-based on mobile and only scrub subtle things (parallax, card stack) with smoothing (`scrub: 0.6–0.8`), each `.pin-graphic` parallaxes with `yPercent` only (so it doesn't fight `enterEl`/`leaveEl`, which tween `y`/`scale`/`rotate`), particles are pushed by the finger (`touchstart/move`), buttons/cards get press feedback via gsap (not CSS `:active` — GSAP keeps an inline `scale` that would override it), and the mobile menu links stagger in on Bootstrap's `show.bs.collapse`. On ≤767px the "Proč já" cards become a CSS `position: sticky` stack (`.values-stack`, added by JS) where earlier cards scale down and darken slightly with `filter: brightness(.8)`; they keep the translucent glass look and `backdrop-filter: blur` hides the text of the card underneath — don't use `opacity` for the dimming (text shows through) and don't give them an opaque dark background (it looked far too dark against the teal page); `#section-values{overflow:visible}` there is required because `overflow:hidden` would turn the section into a scroll container and kill `sticky`. Reduced-motion users skip all of this.
- **Portrait photo autoplay (mobile, `startCardAutoplay`)**: each step flies the front card up and out (it keeps the top `zIndex`), advances the others, and only once the flown-out card is invisible does it silently move to the back of the deck and fade in. Never reassign `zIndex` of cards that are visible and overlapping at the start of a transition — the old version did exactly that and the previous front photo visibly "dropped" behind the others (a flicker every tick). The pending timeline is stored on `cards._autoTl` and must be killed whenever the loop stops.
- **Testing gotcha**: `isMobile`/`lowPower` are read once at load, so a `matchMedia("(max-width: 991px)")` listener calls `location.reload()` whenever the viewport crosses 991px. When driving the page with Playwright/devtools, wait ~1.5s after resizing across that width before navigating or reloading, otherwise the two loads collide (`net::ERR_ABORTED`). Also test the "reload while already scrolled down" case — scroll restoration exercises the pin setup differently from a load at the top.
- **Contact form**: still Netlify Forms (`data-netlify="true"`, honeypot `bot-field`, hidden `form-name` field — all required for Netlify to detect/accept it), but `script.js` now submits it via `fetch` POST to `/` (urlencoded, Netlify's AJAX pattern) and swaps the form for an inline `#formSuccess` panel instead of redirecting to Netlify's generic page. If the fetch fails or returns non-2xx it falls back to the native `form.submit()`, i.e. the old behaviour — don't remove the hidden `form-name` input or the `<form>` attributes, or Netlify stops receiving submissions. Invalid fields shake (`invalid` event, capture phase). Only works for real on the deployed site: a local `python3 -m http.server` can't handle POST, so test with Playwright `page.route` mocking (filter same-origin POSTs — analytics beacons are POSTs too).
- **Contact copy buttons**: `.copy-btn[data-copy]` next to the phone/e-mail links (the links stay — `tel:`/`mailto:` are the primary action); a `#copyToast` live-region element is created by JS. Clipboard API with a `execCommand` fallback.
- **Mobile hero mini code** (`.hero-mini-code`, `d-lg-none`): replaces the desktop-only code panel on small screens; its lines "type in" via a standalone `gsap.from(width)` tween (deliberately not inside `heroTl`, whose 1.6s safety `setTimeout` would cut it short). Lines use `width: fit-content` so the typing ends exactly at the text.
- **Particles & scroll**: each frame `drawParticles` reads the scroll delta — particles shift against the scroll direction by size-dependent amounts (depth) and fast scrolling boosts the drift; disabled under `prefers-reduced-motion`. The depth shift uses `scrollShift`, an exponentially smoothed `dy` (×0.18), **not** the raw per-frame delta: scroll position is reported unevenly (e.g. only every 3rd frame), and the raw value made the dots lurch and stand still in between. The smoothing keeps the total shift identical but spreads it over frames. Keep the mouse-block variables named `mdx`/`mdy` — a `var dx, dy` inside the `forEach` callback is hoisted over the whole callback and silently shadows the outer scroll `dy` (this killed the scroll parallax for months).
- **Measuring particle distribution** (regression check after touching the particle code): expose the array by injecting `window.__P = particles;` before `function drawParticles() {` via a Playwright `page.route` on `script.min.js` (fulfil with `script.js`), then scroll down and back up several times and count particles inside the viewport / the middle 80% / the outer 5% band. Healthy: ~90–98 of 98 inside, ~55–68 in the middle, ≤25 at the edge. The failure mode is the opposite (middle ≈ 0, edge ≈ 95).
- **Scroll performance on Chrome**: `ScrollTrigger.create({ start: 0, end: "max", onUpdate })` writes six CSS custom properties on `document.documentElement` every scroll tick (`--grad-a`, `--grad-b`, `--grad-angle`, `--glow-a`, `--glow-b`, `--scroll-progress`). Custom properties inherit, so each write invalidates styles for the whole document: removing the writes cut style recalculation 444 → 121 ms and total main-thread time ~25% over 150 wheel ticks. Not changed yet (only a few elements consume these vars: `#bg-layer`, the two blobs, the navbar progress line, `.pin-graphic .blob`), but if scroll jank on Chrome comes up again, write them on those elements instead of `:root`. Other measured main-thread costs during scroll: the deferred GTM script (~as expensive as the particle loop, ~0 when idle) and ~5–6 style recalcs per tick. The particle loop, link lines, `backdrop-filter` and `filter: blur` were each switched off in A/B runs without changing the slow-frame count. A choppy Chrome that is fine in Chrome Beta / a clean profile is an extension or browser-setting problem, not the code.
- **Tooling gotchas**: the Playwright MCP's `browser_run_code_unsafe` has no `require`, so fetch `script.js` inside the `page.route` handler instead of reading it from disk; the real Chrome can't be driven by the chrome-devtools MCP here (`DevToolsActivePort` EPERM). `npx playwright install webkit` hung while unpacking (twice, ~6 min with no progress) — a real Safari check has to be done by the user on a device (serve the repo with `python3 -m http.server` and open `http://<Mac-IP>:8000` on the iPhone).
- **Open, unverified: "Proč já" sticky stack on iOS Safari** shakes when a card sticks. In Chromium emulation the stuck cards are perfectly still (0 px position jitter), so it's a Safari rendering issue. Prime suspect: `gsap.fromTo(card, { filter: "brightness(1)" }, { filter: "brightness(0.8)" … scrub: 0.6 })` animates `filter` on an element that also has `backdrop-filter: blur(18px)` (Safari re-renders the backdrop on every change). Candidate fixes to A/B on a device: dim with an overlay pseudo-element's `opacity` instead of `filter`; drop `backdrop-filter`; `scrub: true`.
